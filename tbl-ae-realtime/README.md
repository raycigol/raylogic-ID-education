## 每堂課參與組別設定

安裝及驗收請見 [PARTICIPATION-DEPLOYMENT.md](PARTICIPATION-DEPLOYMENT.md)。先安裝後端遷移，再部署前端；已於 2026-11-02 完成 Supabase 結構查核、遷移與 TEST 回滾驗收，全部既有課堂資料指紋保持相同。

## 流程
1. Supabase Authentication 中已啟用 Anonymous Sign-Ins，且建立教師 email/password。
2. 由教師使用 SQL Editor 私下將每組 tbl_team_invites.join_code 提供該組代表（不要將清單放進 GitHub）。
3. 教師登入 teacher.html 開放 Stage 1。學生在 student.html 輸入代碼加入。
4. 各組選 A–E 提交，教師端每 4 秒更新提交數；全部參與組別提交 後才能鎖定。
5. 教師鎖定並按公布，成績頁才能看見該階段分數，下一 Stage 才能開啟。
6. 學生頁不顯示病例、答案解析或正解。

## 注意
- 目前使用每 4 秒輪詢，非真正 WebSocket Realtime push。
- 完全依賴 Supabase 既有 SQL tables/RPC/RLS 設定；未做實際跨手機測試，課前務必先用不同裝置測試。
- **安全待驗證**：SECURITY DEFINER 函式、教師角色、student join code、鎖定與提交競爭、已公布成績是否受到防提前洩漏保護。
- 不要在公開 GitHub 放 secret key、資料庫密碼或 13 組 join code。config.js 只可放 Supabase 公開 publishable key。
- 舊有單機及快照查分版保留不動。

## 學生離開與課堂重置
- 學生按「離開組別／重新加入」可登出本機，再輸入正確代碼；不刪除原組答案。若已替錯誤組別作答，須通知教師處理，離開不能撤回答案。
- 提交前會顯示組別與答案供確認。教師登入不會被學生離開按鈕登出，請以獨立瀏覽器測試學生。
- 教師「重置本課堂」永久清除所選課堂的全部答案及分數，四階段回到未開放、active_stage 回到 1，保留組別、加入代碼及既有學生綁定。課前應重新核對組別代表。
- 重置前先另存需要保留的成績。確認視窗會完整列出課堂及影響範圍，只需輸入「重置」兩字再按確認，不必重打課堂名稱。伺服器仍核對課堂擁有權與原始完整名稱，並鎖住階段後在單一交易內執行。其他課堂不受影響。
- 新環境須先執行 `sql/reset-session.sql`。安裝函式本身不會清除任何課堂；只有呼叫重置才會刪除。
- 學生回歸測試：`node tbl-ae-realtime/tests/student-leave.cjs`。

## 六碼加入碼與 QR Code
- 教師登入後選擇課堂，切換「加入碼與 QR」分頁，按「產生／查看本課堂加入碼」。每組一個六碼代碼，不分大小寫，排除 0/O、1/I/L。不要公開整班代碼或提交至 GitHub。
- QR Code 在本機由隨附 qrcode-generator 1.4.4（MIT）產生，不呼叫外部 QR API。連結把代碼放在 URL fragment；學生頁讀入後移除 fragment，僅帶入欄位，不自動加入。
- 學生輸入短碼或原 UUID 皆可加入，仍遵守一組一位代表規則。已加入他組時先離開；若該組已有代表，請聯絡教師，不會覆蓋原代表或答案。
- 「更新此組短碼」會停用舊短碼／QR Code，保留已加入學生與原 UUID。舊短碼不重複發給別組。課堂重置也保留短碼，需要更換時另按更新。
- 新環境先執行 `sql/short-join-codes.sql`。新增資料表開啟 RLS 並禁止學生直接讀取；教師管理函式核對課堂擁有權，學生加入沿用原本 UUID 加入函式。
- 新加入入口每個匿名帳號每分鐘最多 5 次嘗試（含失敗），回傳失敗結果而不拋出例外，以保留計數；超限後等一分鐘。這是帳號限制，匿名帳號建立仍受 Supabase Authentication 既有速率設定管理。原 UUID RPC 保留相容性。
- 學生記住所選課堂，成績頁依此查詢；若已無該課堂資格，不會自動切換到其他課堂。

## 組別代表管理
- 教師選擇課堂，切換「組別代表」分頁，按「重新整理代表狀態」。顯示各組已綁定代表數及已提交階段，這不是即時在線人數。
- 「解除代表綁定」只解除該組操作資格，答案與分數保留；新代表可用原加入碼加入。解除不會刪除匿名帳號，也不會登出其他課堂。
- 「解除並更新短碼」同時讓舊短碼／QR Code 失效，但原 UUID 仍有效。持有有效代碼的人仍能重新加入；這是換代表工具，不是永久封鎖帳號。
- 解除時伺服器核對教師擁有權、課堂名稱、組別及畫面所載代表清單。若已換代表，舊畫面不能誤解除新代表，需重新整理後再確認。
- 提交函式鎖住代表綁定直到提交完成。解除會等待已在處理的提交結束；解除完成後，未重新加入的舊代表不能再取得該課堂學生狀態、成績或提交答案。已載入裝置的內容無法收回，學生頁下次刷新會移除操作區。
- 「重置課堂」可勾選「同時解除本課堂全部代表」，預設不勾選。無論是否解除代表，都保留組別、UUID 及短碼；重置仍會清除答案與分數。
- 教師頁上方固定顯示所選課堂與三個功能分頁。「課程控制」包含階段操作與成績，重置收在底部「課後重置設定」內。切換功能分頁不變更課堂，也不會自動產生短碼、解除代表或重置資料；四秒刷新不切回其他分頁。
- 新環境執行 `sql/representatives.sql` 前，先安裝原有 reset-session 與 short-join-codes SQL。安裝本身不會解除任何代表。新前端重置呼叫 `tbl_teacher_reset_with_members`，舊兩參數重置仍保留相容性。
- 測試：`node tbl-ae-realtime/tests/representatives.cjs`，以及教師、學生、成績、短碼回歸測試。TEST 回滾驗證涵蓋解除保留資料、舊權限撤銷、換代表加入、畫面過期拒絕、更新短碼及重置兩種選項。

## 未鎖定階段撤回單組答案
- 在教師「課程控制」分頁展開「單組答案撤回與更正紀錄」，按「載入答案與更正紀錄」。每筆顯示組別、Stage、原答案與提交時間。
- 只可撤回未鎖定、未公布且尚未計分階段的指定一筆答案，不更動其他組、同組其他階段、綁定、加入碼或成績。撤回後提交數減一，代表可在階段開放時重新提交。
- 確認視窗列出課堂、組別、Stage、原答案及提交時間；在同一視窗填寫 1–500 字原因，輸入「撤回」兩字再確認。前後或中間的空白自動忽略。若學生已更新答案或重新提交，舊畫面不能撤回新答案，必須重新載入。
- 若是錯誤代表誤送，先在「組別代表」解除錯誤代表，再撤回受影響答案，讓正確代表加入。撤回答案本身不會解除代表。
- 伺服器核對教師、課堂、組別、完整提交快照與階段狀態，鎖住階段及該提交後，在同一交易內寫入更正紀錄並刪除答案；失敗時一併回滾。
- `tbl_answer_corrections` 保存完整原提交（含原提交者、時間）、課堂與組別名稱、原因、撤回教師及時間；前端無直接讀寫權限，只能由所屬教師的檢閱函式取得。課堂重置將本次紀錄封存，畫面「本次課堂更正紀錄」清空，舊資料可在「歷史封存紀錄」查看；兩區各顯示最近 100 筆。
- 新環境先依序安裝原有 reset-session、short-join-codes、representatives、withdraw-answer SQL，最後執行 `sql/archive-corrections.sql`，使原有重置入口及代表重置入口都套用封存行為。重跑舊的 reset-session SQL 後也須重跑 archive-corrections。安裝本身不重置課堂、不封存既有紀錄；既有紀錄於下一次所屬教師確認重置時封存。
- 封存與答案、分數清除在同一交易完成，只處理所選課堂。重置僅填入尚未封存紀錄的 archived_at，保留所有原始內容，重複重置不改寫舊封存時間。新撤回紀錄預設 archived_at 為空，列入本次課堂。
- 前端測試：`node tbl-ae-realtime/tests/answer-review.cjs`。資料庫回歸測試：在 Supabase SQL Editor 執行 `tests/withdraw-answer.sql`，只使用指定 TEST fixture，建立臨時測試資料後完整回滾；比較其他組、其他階段及正式課堂未變，並驗證更正紀錄、重新提交、封存、新課堂分離與重複重置。
- 確認視窗開啟時暫停刷新並鎖住課堂選擇；取消或按 Escape 不會操作資料。前端用已顯示的完整名稱產生原有 API 確認參數，沒有放寬後端的課堂、組別、階段與提交快照檢查。視窗測試：`node tbl-ae-realtime/tests/confirmation.cjs`。

## 課堂搶答（獨立積分）
- 教師切換「課堂搶答」分頁，先按「開啟搶答功能」。學生頁此時會顯示搶答按鈕，但按鈕停用並提示等待教師；功能開關與每輪開放狀態分開。
- 教師準備好後按「開啟新一輪」，學生才能按「搶答！」。只有第一個抵達伺服器的有效請求取得回答權；網路延遲會影響順序，不依手機時間排序。頁面每秒更新狀態。
- 結束本輪後，學生仍可看到停用的按鈕與積分，等待下一輪。教師按「關閉搶答功能」才會隱藏學生搶答區，並結束進行中的輪次；既有得主、積分與判分紀錄保留。再次開啟功能不會重開舊輪次。課堂重置則關閉功能並封存輪次。
- 開關保存在各課堂的 buzzer_enabled，不會切換其他課堂。學生無法透過搶答介面開關功能；伺服器同時檢查功能已開啟、輪次可搶答及代表資格，關閉功能與搶答使用同一課堂鎖序列化。首次安裝此開關時，原本已有進行中輪次的課堂保留為開啟，其餘預設關閉；重跑安裝不改動既有開關。
- 教師可「結束本輪」停止接受搶答。有得主後即可開下一輪；答錯不自動轉給其他組，如要再搶，開新一輪。學生不能自行開輪、結束或給分。
- 在得主的該輪填入最終分數（0–100 整數），再按「設定分數」。原因選填，留白會自動記為「教師判分」，仍保留原分數、新分數、教師及時間。這是設定該輪分數，不是重複累加；更正時核對原分數，舊畫面不能覆蓋已更新分數。教師可查看最近 100 筆判分紀錄。
- 搶答積分由各輪加總，與四階段答案、已公布成績、排名及原成績 CSV 分開。各課堂隔離；學生只能查看已加入課堂的得主與搶答積分，不能看教師判分紀錄。
- 伺服器鎖住該輪判定唯一得主；重複請求不重複得分，晚到的其他組不能取代得主。每次請求都帶課堂及輪次 ID；關閉／封存的輪次無法搶答，舊輪次不會被轉到新輪次。解除代表後即失去搶答資格。
- 課堂重置在原交易內封存搶答輪次、關閉搶答並使目前積分歸零；舊輪次及判分紀錄仍留在資料庫。安裝本身不開啟搶答、不重置或修改既有課堂資料。
- 安裝順序：完成原有 SQL（最後為 archive-corrections）後執行 `sql/buzzer.sql`。之後若重跑舊 reset-session 或 archive-corrections SQL，須再執行 buzzer.sql 以保留重置封存行為。
- Supabase TEST 回滾驗證：執行 `tests/buzzer.sql`，僅使用固定 TEST 課堂建立臨時代表與輪次，驗證後比較所有課堂資料快照並完整回滾。已於實際資料庫驗證成功，正式課堂與既有 TEST 資料均保留。
- 前端測試：`node tbl-ae-realtime/tests/buzzer-ui.cjs`。隔離資料庫測試使用 PGlite：先於臨時目錄安裝 `@electric-sql/pglite`，再執行 `node tbl-ae-realtime/tests/buzzer-db.cjs /臨時目錄/node_modules/@electric-sql/pglite /專案/tbl-ae-realtime/sql`。測試只建立本機合成資料，涵蓋權限、唯一得主、重送、過期輪次、分數更正、代表解除、課堂隔離與重置；PGlite 的重疊請求會排隊執行，未模擬正式資料庫多連線鎖競爭。

## 學生查看本組已提交答案
- 作答頁持續顯示伺服器已接受的「本組已提交：A–E」，鎖定或公布後仍保留；鎖定／公布階段不提供修改按鈕。尚未提交、撤回或重置後顯示「本組尚未提交」。
- 只使用既有學生狀態介面的本組答案，依目前加入課堂篩選，不讀取其他組答案或未公布成績；選取但尚未提交的選項不會冒充已提交答案。
- 測試：`node tbl-ae-realtime/tests/student-answer.cjs`。

## 成績 CSV 匯出
- 教師在「課程控制」的「已公布分數」區按「匯出成績 CSV」，下載目前所選課堂的參與組別成績。匯出時重新呼叫既有已公布成績與教師組別檢閱函式；不讀取未公布原始分數、不變更資料。
- 欄位：課堂名稱、課堂 ID、組別編號／名稱、S1–S4、已公布累計、排名、台北匯出時間。未公布階段留白；完全沒有公布分數的組別，累計及排名也留白；實際公布的 0 分仍保留。
- 使用與成績表相同的累計及並列排名規則，組名取自所選課堂。檔名含課堂名稱、台北日期時間與課堂 ID 前八碼，方便區分 TEST／正式課堂。
- CSV 使用 UTF-8 BOM 與 CRLF，供 Excel 開啟；逗號、引號與換行正確跳脫，文字欄位防止被當成試算表公式。不輸出答案、學生身分或加入碼。
- 匯出時暫停教師操作與課堂切換；登入、課堂變動或讀取失敗時不下載。重置前先自行匯出所需成績，匯出功能不會自動重置或公布分數。
- 測試：`node tbl-ae-realtime/tests/score-export.cjs`。
- 測試：`node tbl-ae-realtime/tests/join-codes.cjs`、`node tbl-ae-realtime/tests/scores-session.cjs`，以及前述學生／教師回歸測試。資料庫已以 TEST 回滾驗證加入、輪替、失效碼、嘗試限制與正式課堂隔離。
